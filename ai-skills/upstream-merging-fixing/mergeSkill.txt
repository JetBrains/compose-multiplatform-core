# Fix build

## Find commits

- Find `mergeCommit`. Stop if it is not a merge commit.
- Find the merged `upstreamCommit` from its parents.
- Use the commit before `mergeCommit` as `resetForkCommit` only if its message starts with `Reset to AOSP to solve conflicts`.
- Use `upstreamCommit` as the upstream context and `resetForkCommit` as the fork context.

## Follow these principles

- Check with `./gradlew publishComposeJbToMavenLocal '-Pcompose.platforms=desktop,web,linux'`.
- Avoid changing `commonMain` unless another target cannot work without it or important non-Android functionality was removed. Make any change minimal and non-intrusive.
- Use `androidMain` changes to determine what other targets need.
- If a new API is needed, find the latest version in `libraryversions.toml` and update `redirectversions.toml` if necessary.
- Do not change upstream-only files such as `buildSrc`, `build.gradle` when `build-fork.gradle` exists, or `someStubMain`.
- Apply only relevant `build.gradle` changes to `build-fork.gradle`.
- Add only the code needed to compile and don't crash in runtime
- Avoid comments. For deferred implementations, add `// TODO(Merge) Implement after merging <upstreamCommit>`.

## Revert the reset

If `resetForkCommit` exists:

1. Run `git revert <resetForkCommit>`.
2. Resolve conflicts using `upstreamCommit` and `resetForkCommit`. 
3. Fix the build until green.
4. Commit as `(AI) Revert <resetHash>`.
5. If there is nothing to revert, create `git commit --allow-empty -m "(AI) Nothing to revert for <resetHash>"`.

## Finish

- Run the build, fix until green
- Commit the fix with a message starting `(AI) Fix `.
